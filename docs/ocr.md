# ゲーム画面のスクリーンショットをブラウザ内でOCRする仕組み（徽章一覧の読み取り）

この文書は、同じような機能を AI に実装してもらうときの参考資料です。AI に渡せば、そのまま読める書き方にしています。
対象は Stella Sora の「徽章一覧」の画面ですが、**白い表の中に「項目名 ＋ 値」の行が並ぶ画面** なら、ほかの画面にも同じ考え方で使えます。

- 状態：本番で公開中（「テスト中」の表示つき）。2026-11-04 時点。
- 読み取りのコード：`sim_ocr.js`（約150行。画面とは切り離してあり、`window.SIM.ocrEmblem` だけを外に出す）
- 画面のコード：`sim_ui.js` の `ocrPots` `ocrBox` `runOcr` `applyOcr`、`paste` イベント、`ocr-clip:` ボタンの処理

---

## 1. 前提と方針

| 項目 | 内容 |
|---|---|
| OCR ライブラリ | Tesseract.js **5.1.1**（`https://cdn.jsdelivr.net/npm/tesseract.js@5.1.1/dist/tesseract.min.js`） |
| 読み込むタイミング | 読み取りを始めたときに `<script>` を足して読み込む。ページを開いただけでは読み込まない |
| 言語データ | `jpn`（項目名）と `eng`（数字）。初回だけダウンロードされ、2回目からはブラウザに残る |
| 画像の扱い | **ブラウザの中だけで処理し、サーバーには送らない。** サーバー費用もかからない |
| 結果の入れ方 | すぐには入れない。一覧で見せて、利用者が「この内容で入れる」を押したときだけ入れる |
| ビルド | 不要。素の JavaScript（ES2017 以上、`async/await` を使用） |

## 2. 画像の入力（3通り）

どれも最後は `File`（または `Blob`）を `runOcr(id, file)` に渡すだけです。

### 2-1. 「クリップボードから読み込む」ボタン（`navigator.clipboard.read`）

```js
if (!navigator.clipboard || !navigator.clipboard.read) {
  ng("このブラウザでは、ボタンからクリップボードを読めません。この画面で Ctrl+V（スマホは長押しで貼り付け）をしてください。");
  return;
}
navigator.clipboard.read().then(async items => {
  for (const it of items) {
    const ty = it.types.find(x => /^image\//.test(x));
    if (ty) { const b = await it.getType(ty); runOcr(id, new File([b], "clipboard", { type: ty })); return; }
  }
  ng("クリップボードに画像がありません。ゲームの画面をコピー（スクリーンショット）してから押してください。");
}).catch(() => ng("クリップボードを読めませんでした（許可されていないかもしれません）。この画面で Ctrl+V をしてください。"));
```

注意点：

- **ボタンのクリックの中で呼ぶこと。** 利用者の操作の中でないと、ブラウザが拒否する。
- 初めて使うときに、ブラウザが「クリップボードの読み取りを許可しますか」と聞くことがある（Chrome など）。拒否されると `catch` に来る。
- HTTPS（または localhost）でないと `navigator.clipboard` 自体がない。
- 古いブラウザや一部のブラウザには `clipboard.read` がない。そのときは Ctrl+V に案内する。
- `items` の中に画像の型（`image/png` など）が無ければ、「画像がない」と伝える。
- Windows では「Win+Shift+S」や「PrtSc」で撮った画像がクリップボードに入るので、そのままボタンを押せる。

### 2-2. Ctrl+V で貼り付け（`paste` イベント）

```js
document.addEventListener("paste", ev => {
  if (!/^emb:/.test(V.panel || "")) return;            // 徽章の画面を開いているときだけ
  const f = [...((ev.clipboardData && ev.clipboardData.files) || [])].find(x => /^image\//.test(x.type));
  if (!f) return;                                       // 画像でなければ、ふつうの貼り付けのまま
  ev.preventDefault();
  runOcr(G.team[V.panel.split(":")[1]], f);
});
```

注意点：

- **許可を聞かれない**ので、ボタンより確実。ボタンが使えないときの逃げ道にもなる。
- `document` 全体で受けるので、**対象の画面を開いているときだけ**反応させる（ほかの入力欄への文字の貼り付けを邪魔しない）。
- 画像が無い貼り付け（文字だけ）は `preventDefault` しない。
- スマホは「長押し → 貼り付け」になるが、貼り付ける場所（入力欄）が無いとメニューが出ないことがある。スマホではファイル選択のほうが確実。

### 2-3. 「画像ファイルを選ぶ」（`<input type="file">`）

```html
<label class="btn-add">画像ファイルを選ぶ<input type="file" accept="image/*" id="ocr-file" data-id="..."></label>
```

```js
if (t.id === "ocr-file") { runOcr(t.getAttribute("data-id"), t.files && t.files[0]); return; }   // change イベント
```

- `<input>` は CSS で隠し、`<label>` をボタンの見た目にしている。
- 読み取り中は `disabled` にする（二重に読まない）。

### 2-4. 画面に出す説明文（実際の文言）

> 「徽章一覧」を一番下までスクロールして撮った画像を、クリップボードから読み込むか、ファイルで選んでください（この画面で Ctrl+V もOK！）。画像はお使いのブラウザの中にてJavaScriptを使って処理されるため、どこにも送信されません。

「どこにも送信されない」ことを書くと、利用者が安心して使える。

## 3. 関数の入出力

### `S.ocrEmblem(file, pots, onMsg, opt) → Promise<rows>`

| 引数 | 型 | 内容 |
|---|---|---|
| `file` | `File` / `Blob` | 画像。上の3通りのどれから来てもよい |
| `pots` | `[[日本語名, 英語名, 項目のキー], ...]` | **その巡遊者の素質だけ**の候補（`ocrPots(id)` が作る）。素質名の当てはめに使う |
| `onMsg` | `(msg: string) => void` | 進み具合の文言を画面に出すため（「準備しています…」「文字を読んでいます…」） |
| `opt` | object（省略可） | 読み比べの実験用。ふだんは渡さない。`pre`（表全体の前処理）、`potRe`（素質名の読み直しの前処理。既定 `"gray"`、`""` で読み直さない）、`psm`、`dpi` |

返り値 `rows`（上から順の配列。1行 = 徽章の1枠）：

| キー | 内容 |
|---|---|
| `k` | 計算で使う項目のキー（`EMBLEM_OPTIONS` の `key`）。素質が見つからない行は `null` |
| `q` | 品質（`gold` / `rainbow2` / `rainbow3` など）。値が読めないと `undefined` |
| `t` | 素質のレベル上昇のときだけ、対象の素質の英語名 |
| `label` | 画面に出す項目名 |
| `warn` | `true` なら「要確認」を出す |
| `part` | `true` なら「（部分一致）」を出す（素質名が1文字だけ違った） |
| `nopot` | `true` なら素質が見つからなかった行（取り消し線＋「（該当無し）」、枠は空にする） |
| `read` `name` `score` | 調べるための生の読み取り結果と近さ |

### 画面側の流れ（`sim_ui.js`）

1. `runOcr(id, file)`：`V.ocr = { busy: true }` にして描き直し → `ocrEmblem` を呼ぶ → 結果を `V.ocr.rows` に入れて描き直す。失敗は `V.ocr.msg` に出す。
2. `ocrBox(id)`：結果を **初級・中級・上級の3列×4行** で見せる。読めた行が12より少ない／多い、該当無しがある、などの注意も出す。
3. `applyOcr(id)`：「この内容で入れる」で、上から4行ずつ 初級→中級→上級 の枠に入れる。行が無い枠・`k` が無い枠は空にする。

## 4. 読み取りの手順（`S.ocrEmblem` の中）

| 順 | 処理 | 決めている数値 |
|---|---|---|
| 1 | Tesseract.js を読み込み、画像を `Image` で開く（`URL.createObjectURL`、使い終わったら `revokeObjectURL`） | — |
| 2 | **白い表の場所を探す**（`findPanel`）。画像を幅240pxに縮め、「ほぼ白」の画素が多い行・列から上下左右を決める | 白 = RGB の最小 > 232。行は幅の25%超が白、列は表の高さの40%超が白。白い行が全体の30%未満なら見つからないとして、PC版の位置（横29〜71%・縦20〜87%）を使う |
| 3 | **切り出して拡大し、白黒にする**（`prep`） | 表の幅が約1800pxになるように拡大（1〜3倍）。明るさ（0.299R+0.587G+0.114B）が150未満なら黒 |
| 4 | **日本語で表全体を1回読む**（`jpn` worker） | `preserve_interword_spaces: "1"`（項目名と値の間の空白を残す） |
| 5 | **値の列だけを数字で読み直す**（`eng` worker） | 表の幅の72〜90%を切り出す。`tessedit_char_whitelist: "0123456789.+%"`、`tessedit_pageseg_mode: "6"` |
| 6 | **行と値を高さで組み合わせる** | 日本語の行の中心の高さに一番近い数字の行。差が行の高さの0.8倍以内 |
| 7 | 行の文字を「名前」と「値」に分ける | 空白2つ以上で分ける。無理なら、うしろの数字の部分を値にする |
| 8 | **項目名を当てはめる**（`best`） | 候補との編集距離 ÷ 候補の長さ。0.5より大きい行は表の行ではない（見出し・背景）として捨てる。0.3より大きいと「要確認」 |
| 9 | **値を品質の段階に当てはめる**（`snap`） | 下記 5-2 |
| 10 | 素質のレベル上昇の行（「○○レベル +3」）は、名前の所だけ灰色のまま読み直して、素質の候補に当てはめる | 下記 5-3 |
| 11 | worker を2つとも `terminate` する（`finally`） | — |

項目名の候補は `EMBLEM_OPTIONS` から作る。属性つきの項目は「水属性ダメージ」「火属性ダメージ」…のように6属性分に広げてから当てはめる。

## 5. 分かっていること・工夫（ここが大事）

### 5-1. 行の数と位置は、画面の決まりで決める

- 徽章は1枚に必ず4行。全部で12行。並びは必ず 初級 → 中級 → 上級。
  → **見出しの文字（「初級」など）は読まずに、上から4行ずつ割り当てる。** 見出しを読むより確実。
- 一番下が切れた画面は11行になる。→「最後の1行が読めていません」と出し、空いた枠は手で入れてもらう。13行以上なら上から12行だけ使う。
- **素質が見つからなかった行も、捨てずに場所だけ残す（`nopot`）。** 捨てると下の行が1つずつずれ、別の徽章に入ってしまう。

### 5-2. 値の読み間違いは、決まった値の一覧に当てはめて直す

- 値は品質ごとに決まった数しかないので、読んだ数字をその一覧に当てはめる。
- 「12%」が「129%」のように、うしろに余計な数字が付くことがある。→ 完全一致が無ければ、**頭が一致する値**（長いほう優先）にする。
- 「+3」の「+」が「1」に読まれて「13」になることがある。→「1」のうしろが1〜3の1文字なら、頭の「1」を外す。+1 は金、+2・+3 は虹。

### 5-3. 素質名（色つき・下線つきの文字）は崩れやすい

- 例：「閃光の奥義」が「関光の和央閉」になった。「閃」はほぼ必ず「関」に読まれる（拡大しても直らない）。
- **候補を、その巡遊者の素質（主力・支援・汎用）だけに絞る**（`ocrPots`）。候補が少ないので、崩れていても当たりやすい。
- 近さは、**編集距離の割合** と **「1 − 最長共通部分列の割合」** の平均（0が完全一致）。崩れた文字が多くても、合っている文字の数で選べる。
- **名前の所だけ灰色のまま読み直す。**
  - 白黒にすると色文字が崩れる。でも灰色のまま表全体を読むと、左にある色の帯（「ステータス」などのラベル）まで文字として読んで、行が崩れる。
  - そこで、表全体は白黒で読み、素質の行だけ、灰色の画像から名前の所を切り出して読み直し、近いほうを使う。
  - 切り出す左端 = **項目名の列の始まり**。ほかの行を白黒で読んだときの、最初の文字の x 座標の **中央値**（どの行も項目名は同じ x から始まり、左の色の帯は白黒では読まれないため）。右端は表の幅の72%。上下は行の高さの35%ずつ広げる。
  - 読み直した文字は、頭の記号と「主力素質／支援素質／汎用素質」を取り除いてから当てはめる。
- 当てる条件：
  - **1文字だけ違う**（1文字足りない・多い・違う。編集距離1）→ 当てて「（部分一致）」と出す。
  - または、近さが **0.5以下** → 当てる。
  - どちらでもない → 「該当無し」。
- 「要確認」：近さが0.3より大きく、1文字違いでもないとき。または値が読めないとき。

### 5-4. やってみてダメだったこと（同じことを試さないために）

| 試したこと | 結果 |
|---|---|
| 素質名の読み直しの左端を「表の幅の◯%」で決める | 0.30 だと左の色の帯の文字が混ざる。0.34 だと「閃」が切れる。画面ごとに違うので、割合では決められない |
| 素質名の読み直しの左端を「その行で最初に読めた文字」で決める | スマホの低い解像度では、色文字の素質名が白黒で消えて「レベル」だけが読まれ、名前の右から切ってしまった → 中央値に変えた |
| 2番目の候補より0.1以上近ければ、近さ0.8まで当てる | 別の巡遊者の画面を読ませたとき、似た名前の素質に当たってしまった（セイナの「関光の奥表」→ ティリアの「閃光の加護」）→ やめた |
| 表全体を、灰色のまま／色の濃い画素も黒に／Sauvola（場所ごとに境を変える）で読む | どれも左の色の帯を文字として読んで、行の読み取りが崩れた（47行中、正しい行は1〜7） |
| `tessedit_pageseg_mode: 6`・`user_defined_dpi: 300` を名前の読み取りに足す | 今とまったく同じ結果（Tesseract.js の初期設定がもともと PSM 6 のよう） |
| 読み直しの切り出しを1.5〜2倍に拡大 | 変わらないか、悪くなった |

### 5-5. 速さ

- 試作は1枚13秒。今は白黒だけなら1枚 約2.6〜3秒、素質の行の読み直しを入れて約4〜5.5秒（PC）。
- 初回だけ、Tesseract.js の部品と言語データのダウンロードの時間が加わる。
- worker は読み取りのたびに作り、終わったら `terminate` している（使い回しはまだしていない）。

## 8. 別の画面・別のゲームに使うときの手順（AI 向けの要点）

1. 入力は 2章の3通りをそのまま使う（ボタン＋Ctrl+V＋ファイル）。画面を開いているときだけ `paste` に反応させる。
2. 表の場所は「背景と違う色の、大きな四角」を縮小画像で探す。見つからないときの固定の位置も用意する。
3. 表全体は **白黒** にして読む。色つきの帯やアイコンが行を崩すので、灰色・カラーで全体を読まない。
4. 数字の列は **別の worker で、使う文字を数字に限って** 読み直す。
5. 名前は **候補の一覧に当てはめる**（編集距離）。候補はできるだけ絞る（その画面に出うるものだけ）。
6. 値は **決まった値の一覧に当てはめる**。
7. 行の位置は画面の決まり（1枚に何行、どの順）で決め、読めなかった行も場所は残す。
8. 色文字など崩れやすい所だけ、灰色で切り出して読み直す。左端は「ほかの行の最初の文字の x の中央値」。
9. 結果はすぐ入れず、一覧で見せて利用者に確かめてもらう。「部分一致」「要確認」「該当無し」を分けて出す。
10. ゆるく当てすぎない（別の画面を読ませたときに、それらしい間違いが入るほうが困る）。
